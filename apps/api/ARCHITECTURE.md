# API Architecture (`apps/api`)

NestJS 11 REST API under the global prefix `/api/v1` (Swagger at `/api/docs`). Prisma 6 → PostgreSQL 16, schema in `prisma/schema.prisma`. Each feature is a module in `src/` (module → controller → service → DTOs); the controller is the reference for its endpoints. Modules with traps have their own `AGENTS.md`.

## Request pipeline

- **Validation**: global `ValidationPipe` with `whitelist` + `forbidNonWhitelisted`. Endpoints that must see the raw body (OAuth, MCP) take untyped input and parse it themselves.
- **Auth**: JWT access + refresh tokens (`src/auth/AGENTS.md`). Google OAuth routes exist only when `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are both set. `health`, `app-config` (`GET /config`, public flags only) and the OAuth discovery endpoints are unauthenticated; the running version is never exposed on a public endpoint.
- **Roles**: `User.role` is `USER` or `ADMIN`; the first real user is the admin (`auth/AGENTS.md`). `AdminGuard` runs after `JwtAuthGuard`, and `JwtStrategy` re-reads the role on every request, so a role change applies without a new sign-in.
- **Rate limiting**: there is no global `ThrottlerGuard`. OAuth and MCP routes apply it locally with `@Throttle`.
- **Trust proxy**: `TRUST_PROXY_HOPS` sets Express `trust proxy`, which decides `req.ip` and so every per-IP limit. Too low makes limits spoofable via `X-Forwarded-For`; too high makes one global bucket. Behind Cloudflare plus a proxy, use 2. All Claude connectors share Anthropic's egress range, so they share per-IP limits.
- **Public URLs** come from env only (`PUBLIC_URL`, or `API_PUBLIC_URL` / `WEB_APP_URL`; `config/public-url.ts`), never from request headers.
- **Same-origin SPA**: when `WEB_DIST_DIR` holds a built web app, `config/spa.ts` serves it with an SPA fallback. `/api`, `/.well-known` and missing file-like paths 404 instead. Every response carries `frame-ancestors 'none'` and `X-Frame-Options: DENY`.

## Data

- Every entity is soft-deleted (`deletedAt`), so FK cascades never fire on delete: clean up dependent rows yourself. Exceptions, hard-deleted on purpose: `account_balance_snapshots` (append-only), `reimbursement_allocations`, and the demo user's rolling-window trim.
- Secrets (`JWT_SECRET`, `JWT_REFRESH_SECRET`, `CREDENTIAL_ENCRYPTION_PEPPER`) come from env, else `DATA_DIR/secrets/<NAME>`, else are generated there on first boot (`config/secrets.ts`). There are no hardcoded fallbacks.
- **One-shot data backfills**: `data_backfills` holds one marker row per backfill. Claim the marker in the same transaction as the work, so a failure retries on the next boot (example: `categories/category-icon-backfill.service.ts`). Use a new marker name per backfill; never reuse one.
- Imports from banks and Google Sheets both land through `transactions/transaction-import.service.ts`.

## Attachment storage (`transactions/attachments`)

- Attachment bytes live in a private S3-compatible bucket, never in the database. The API is the only reader; the bucket is never exposed.
- Configured by `ATTACHMENTS_S3_*` (parsed in `attachment-storage.config.ts`, same rules as the deploy webhook). Unless the endpoint, bucket and both keys are set, uploads return 503 and `/config` reports `attachmentsEnabled: false`.
- Always path-style addressing; checksums only when a request requires them, for S3-compatible services that reject the SDK defaults.
- Keys are `attachments/<userId>/<uuid>`, thumbnails `<key>-thumb`. The user's file name is only a display name on the row and never reaches a key.
- Deletes from the bucket are best effort (`deleteObjects` never throws), so a failed delete leaves an orphan object rather than an error.

## Build (SWC)

- `nest build`, watch mode and Jest (`@swc/jest`) all compile with SWC and never type-check. `pnpm check-types --filter=api` is the only type check, and CI doesn't run it.
- The seed compiles separately with `tsc` to `dist-seed/` (`tsconfig.seed.json`) and has no path-alias support; use relative imports.
- The image ships only the production dependency graph (`pnpm deploy --prod`). `@badger/types` is a devDependency with TS source, so import it with `import type` only: a value import crashes the container at boot (guarded by `src/badger-types-imports.spec.ts`).
- `@swc/core` is pinned to exactly `1.16.2`: newer releases fail to load their native binding on Windows (swc#12442). Drop the pin once a release loads on default Windows ACLs.

## Running version and updates (`system`)

- `APP_VERSION` and `GIT_SHA` are stamped into CI images. Without them the API reports `<package version>-dev`, which never shows an update.
- `UpdateCheckService` reads the latest GitHub release of `UPDATE_CHECK_REPO` at boot and then at most daily; `UPDATE_CHECK=false` makes no request.
- What's New entries come from the bundled `apps/api/changelog.json` (generated by the release workflow). A missing or invalid file yields no entries.
- **In-app upgrade** (`upgrade.service.ts`, admin only) POSTs to the host's deploy webhook (`DEPLOY_WEBHOOK_*`, parsed in `deploy-webhook-config.ts`). The URL, token and body are secrets: never return or log them, not even in error messages (`err.message` can contain the URL). Redirects aren't followed and the response body is never read. An invalid setting disables the feature with a warning naming only the variable. `upgradeAvailable` in `system/info` depends on the caller, so it is true only for admins.
- Local runs read these variables from `apps/api/.env` only: turbo's strict env mode drops shell variables.

## OAuth and MCP

The API is an OAuth 2.1 authorization server (`src/oauth/AGENTS.md`) for its own read-only MCP server at `POST /api/v1/mcp` (`src/mcp/AGENTS.md`). MCP tokens are opaque and stored hashed, not JWTs. Discovery documents are served at the host root, outside the global prefix (`app.setup.ts`).

## Bank sync

`bank-sync` scrapes Israeli banks with `israeli-bank-scrapers` + `puppeteer-extra`, either on a remote Browserless (`BROWSERLESS_URL`) or local Chromium. Credentials are encrypted with the user's sync PIN (`crypto`), never stored in plaintext. Details: `src/bank-sync/AGENTS.md`.
